# SimpleReminder

> 一个节拍器,每隔一段时间从你勾选的休息方式里随机抽一个,**全屏**推到你面前,按住一秒可以跳过。

一个 Chrome 扩展形态的健康休息提醒工具。无账号、无服务端、无数据上传。

---

## 当前状态

**完整的一轮已经跑通了:** 预告条滑下来 → 你可以按 Esc 延迟 → 不延迟就全屏
→ 按住一秒可以跳过 → 按正常间隔排下一轮。

它还知道你什么时候不在:**离开电脑超过 5 分钟就算已经休息过了**,
回来不会被糊一脸,整个周期从你回来那一刻重新算。
扩展图标上的 **badge 显示还有几分钟**,暂停时变成 `||`。

v0.1 的实现顺序只剩最后一项(埋点展示)。

## 核心设计速览

**全屏遮挡是功能本身,不是通知的载体。**
角落弹窗说「该看远处了」,用户瞥一眼点掉继续盯屏幕 —— 功能完全没有发生。

| 难题 | 解法 |
|---|---|
| 现代网页 `transform` / `filter` 导致 z-index 失效 | 放弃 z-index,用原生 `<dialog>.showModal()` 的 **Top Layer**;预告条用 `popover`(非模态) |
| 网页 CSS 变量穿透 Shadow DOM | 不用 Shadow DOM 承载 UI,改用 **扩展页 iframe** —— 独立 document,连继承都不存在 |
| MV3 Service Worker 被回收 | **Storage 是真相源**,`chrome.alarms` 只是叫醒服务;幂等 `reconcile()` 自愈补偿 |
| 多标签页各自随机导致双屏显示不同内容 | **每次休息只决定一次的事,一律在 background 决定并写 storage**;iframe 只是显示器 |

**技术栈:** 原生 MV3,零构建 · JSDoc + `@ts-check` · `chrome.alarms` + `chrome.idle` · 原生 `<dialog>` / `popover`
(封板时选的是 WXT + React + Tailwind,实现阶段改为原生 —— 理由见
[ARCHITECTURE §1.1](docs/ARCHITECTURE.md#11-偏离记录wxt--react--tailwind--原生零构建))

## 安装(开发版)

不需要 `npm install`,没有构建步骤。

1. 打开 `chrome://extensions`
2. 右上角打开「**开发者模式**」
3. 点「**加载已解压的扩展程序**」,选这个仓库的根目录
4. 点工具栏里的 SimpleReminder 图标 → 弹出 popup

popup 里能看到**下次休息的时刻和实时倒计时**。点「立即休息」会马上
全屏盖上,20 秒后自动消失 —— **按住「按住跳过」一秒**,或者
**按住 `Esc` 一秒**,可以提前结束。

到点前 8 秒会先有一条**预告条**压在网页顶上。这几秒里:
**按 Esc**(或点那条)= 延迟 5 分钟;**如果你正在输入框里打字,它会自动延后**
并把这件事写在条上 —— 静默的智能行为会摧毁信任,所以它必须说出来。

> 遮罩盖不住 `chrome://` 开头的页面、Chrome 应用商店和 PDF 阅读器 ——
> 这是 Chrome 的限制,不是 bug。见 [ARCHITECTURE §9](docs/ARCHITECTURE.md)。

### 只在部分网站生效?

如果某些标签页毫无反应,**先在 `chrome://extensions` 点一下扩展卡片上的刷新按钮**。

Chrome 只在页面**加载时**注入 content script,安装和更新都不算导航 ——
所以装扩展时已经开着的标签页会漏掉。扩展现在会在安装 / 更新 / 启用时
自动给已打开的标签页补注入,但如果你是直接覆盖文件后手动重载扩展,
偶尔还是需要刷一下页面。

### 怎么确认「它真的会自己响」

⚠️ **点图标 ≠ 验证调度器。** 点图标 / 点「立即休息」是手动触发,
它从第一版起就能用。调度器要验的是**你不操作它也会响**:

1. 在 popup 里把**间隔改成 1**(分钟),焦点离开输入框即生效
2. **关掉 popup,什么都别点**
3. 看着工具栏图标等一分钟 —— 遮罩应该自己盖上来

改完间隔后重新打开 popup,「下次休息」的时刻应该已经重算成一分钟后,
而不是沿用旧的 20 分钟。那一行就是调度器在工作的证据。

### 测试

```bash
node test/run.mjs
```

零依赖,不需要 `npm install`。**189 条断言**,覆盖状态机、补齐逻辑、
睡眠唤醒、自然休息检测、badge、延迟计数、并发去重、重复注入、展示函数。

其中最值钱的一段是末尾的**不变式扫描**:
「没在暂停,就必须有下一次唤醒」—— 10 种状态 × 8 个迁移 × 3 个时间点。
违反它意味着扩展会静悄悄死掉(没有闹钟 = 没有东西唤醒 service worker),
而界面上只表现为「下次休息 `--:--`」,看起来像个显示问题。
加上这条扫描当天就抓出了三处实例。

> 这是**跑在 Node 里的单元测试**,和你浏览器里装的那个扩展实例没有关系 ——
> 它验的是代码逻辑对不对,不是「这次安装有没有生效」。

### 三个地方别搞混

| 在哪里跑 | 怎么进去 | 回答什么问题 |
|---|---|---|
| **Node 终端** | `node test/run.mjs` | 代码逻辑对不对 |
| **Service Worker 控制台** | `chrome://extensions` → 卡片上的 **Service Worker** 链接 | 我这个安装实例现在是什么状态 |
| **浏览器界面** | 点图标 / 等它自己响 | 用起来是什么感觉 |

点扩展图标是**手动触发**,从第一版就能用 —— 它证明不了调度器在工作。
要验「它会自己响」,把间隔改成 1 分钟,**然后什么都别点,等一分钟**。

### 更深的调试

`chrome://extensions` → SimpleReminder 卡片上的「**Service Worker**」链接
→ Console。下面这些是 **JS,粘在那个控制台里**,不是终端命令:

```js
chrome.storage.local.get('runtime', console.log);   // 当前状态机
chrome.alarms.getAll(console.log);                  // next-wake + badge-tick
chrome.storage.local.get('stats', console.log);     // 按条目的埋点
chrome.idle.queryState(300, console.log);           // 它认为你在不在
```

### 不装扩展也能看

```bash
python3 -m http.server 8080      # 在仓库根目录
```

打开 `localhost:8080/demo/` —— popup、预告条、休息屏都能真跑
(假的 chrome API + **真实的** `popup.js` / `content.js`),
调视觉不用反复重载扩展。预告条那页还带一个输入框,专门用来试自动延迟。

## 自用两周:具体盯什么

设计阶段有几个判断是**在纸上拍的,只能靠真用两周来证伪**。
按「最可能错」排序:

**1. `Esc` 延迟会不会和网页自己的 `Esc` 打架。**
预告那几秒里 `Esc` 被我吃掉了。Gmail、Notion、各种编辑器里 `Esc` 都有含义
(关对话框、退出编辑)。如果你发现「我只是想关个弹窗,结果把休息推掉了」,
这个键就得换 —— 备选是 `Alt+Space`,或者干脆只留「点预告条」一条通路。

**2. 20 分钟是不是太密。**
看跳过率(下面有读法)。跳过一半以上基本就说明节奏不对 ——
那是**设置的信号,不是你的失败**。

**3. 长按 1 秒是不是太容易跳过。**
太容易 = 形同虚设;太难 = 真有急事时会骂人。

**4. idle 5 分钟够不够。**
太短:读长文没碰鼠标被判定成「已经休息过了」,从此不提醒。
太长:开完会回来还是被糊一脸。

**5. 遮罩在哪些站点出不来。**
已知硬边界:`chrome://` 页、Chrome Web Store、PDF 查看器 —— 这几类
Chrome 不允许注入,任何扩展都做不到(v0.2 用系统通知兜底)。
除此之外如果还有站点失灵,那是 bug,值得记下来。

**6. 预告条会不会挡住某些站点的顶栏。**
它是通栏贴顶压在页面上方的,8 秒。

### 怎么读埋点(v0.1 没有统计界面)

统计 UI 是 v0.2 的事。但数据从第一天就在记,
粘到 **Service Worker 控制台**里就能看:

```js
chrome.storage.local.get('stats', ({stats}) => {
  const sum = {};
  for (const day of Object.values(stats || {}))
    for (const [id, v] of Object.entries(day)) {
      sum[id] ||= {completed:0, skipped:0, postponed:0};
      for (const k in v) sum[id][k] += v[k];
    }
  console.table(sum);
});
```

要回答的就一个问题:**跳过率高不高。**
高 → 间隔太密,或者某一条内容你根本不想做(那就取消勾选它)。

没有…他们不会等 20 分钟。」* 自用时无所谓(你知道它要干嘛),
但这是上架前必须补的第一件事。

**② 统计 UI 与调参建议(v0.2)。** 不是图表,是一句话 +
一个可执行的按钮:「『去接杯水』你十次有八次跳过 —— 取消勾选?」

不做 streak、不做连续天数 —— 那些会把"没做到"变成一种亏欠。
