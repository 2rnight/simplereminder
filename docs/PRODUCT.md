# SimpleReminder · 产品方案(封板)

> 状态:**已封板** · 日期:2026-10-04
> 本文件是产品层面的唯一真相源。实现中若需偏离,先改本文件再改代码。

---

## 1. 一句话定义

> **一个节拍器,每隔一段时间从你勾选的休息方式里随机抽一个,全屏推到你面前,按住一秒可以跳过。**

---

## 2. 定位

| 项 | 结论 |
|---|---|
| 品类 | 健康休息提醒(Break Enforcer),**不是**通用待办提醒 |
| 形态 | Chrome 扩展。无桌面应用、无账号、无服务端、无数据上传 |
| 目标用户 | 浏览器占工作时间较高比例的人 |
| 自用 / 上架 | 自用优先,顺手上架 Web Store |

### 2.1 核心认知:全屏遮挡是功能本身,不是通知的载体

盖住屏幕,不是为了告诉用户「该休息了」,而是因为**不盖住他就不会休息**。

一个角落弹窗说「该看远处了」,用户瞥一眼、点掉、继续盯屏幕 —— 功能完全没有发生。
只有屏幕被物理遮挡,用户才会抬头。

这也是桌面端同品类(Stretchly / Workrave / EyeLeo / Time Out)二十年来清一色采用全屏的原因。

### 2.2 核心认知:遮罩是「触发器」,不是「容器」

遮罩显示 20 秒后自动消失,**不代表休息必须在 20 秒内结束**。
它说「站起来走两步」,你站起来了,遮罩关掉了,你完全可以继续站着。

**推论:内容文案中不得出现具体时长**(见 §5.3)。

---

## 3. 设计原则(违反即视为 bug)

| # | 原则 | 原因 |
|---|---|---|
| P1 | **单次交互成本必须接近零** | 一天触发约 24 次,任何摩擦被放大 24 倍 |
| P2 | **内容是行动指令,不是信息消费** | 内容若值得读,用户就会盯着屏幕读完,护眼目的完全失败 |
| P3 | **不要求点击确认** | 休息时用户的手不该在键盘上 |
| P4 | **静默的智能行为必须可见** | 自动延迟若无提示,用户会以为扩展坏了 |
| P5 | **信息优于限制** | 不拦截用户的极端配置,而是展示后果 |
| P6 | **误伤的代价远高于漏提醒的代价** | 漏一次护眼没事,打断一次电影可能导致卸载 |
| P7 | **统计用于调参,不用于评判** | 让人产生负罪感的统计,与「让你放松」的产品目标自相矛盾 |

## 4. 完整流程

```
  ┌──────────────────────────────────────────────────────┐
  │ 计时中                                                │
  │  · 扩展图标 badge 显示距下次休息的分钟数                │
  │  · 抑制条件命中则暂停/重置(见 §7)                     │
  └───────────────────────┬──────────────────────────────┘
                          │ 到点前 8 秒
                          ▼
  ┌──────────────────────────────────────────────────────┐
  │ 预告(8 秒)                                          │
  │  通栏贴顶小条,剧透本次内容                            │
  │  ├ 检测到用户正在输入 → 自动延迟(并显示提示)          │
  │  ├ 按空格 / 点击条     → 延迟 5 分钟                   │
  │  └ 无操作              → 进入休息                      │
  │  (此阶段后台预热 iframe)                             │
  └───────────────────────┬──────────────────────────────┘
                          ▼
  ┌──────────────────────────────────────────────────────┐
  │ 休息(用户自定义时长)                                 │
  │  全屏渐暗 + emoji + 行动指令 + 大倒计时                │
  │  ├ 长按「跳过」1 秒 → 跳过(正常间隔重新计时)          │
  │  └ 倒计时归零       → 自动关闭,焦点归还原元素         │
  └───────────────────────┬──────────────────────────────┘
                          ▼
                        计时中
```

## 5. 功能规格

### 5.1 计时

| 项 | 规格 |
|---|---|
| 间隔 | 用户自定义,默认 **20 分钟** |
| 时长 | 用户自定义,默认 **20 秒** |
| 上下限 | **不设硬上限**。技术下限 1 分钟(`chrome.alarms` 粒度 30 秒) |
| 极端值处理 | 不拦截,改为**后果预览**:`间隔 [5] 分钟 ⚠️ 按 8 小时算,一天约 96 次提醒` |
| 精度 | `chrome.alarms`,±30 秒。20 分钟周期下无感,**不做秒级精度方案** |

### 5.2 休息方式(勾选制 + 随机)

用户勾选哪些参与随机;**勾一个 = 永远是那一个**。
勾选本身即是自定义,不需要单独的自定义功能。

**v1 内置 3 条:**

| emoji | 主文案 | 副文案 | 主题色 |
|---|---|---|---|
| 🧍 | **站起来,走两步** | 让腰背松一松 | 暖琥珀 |
| 👁 | **看看窗外最远的地方** | 给眼睛对个远焦 | 深墨绿 |
| 💧 | **去接杯水** | （空） | 深青 |

- 随机算法:**洗牌袋**(一轮内不重复),而非纯 `Math.random()`
- **不允许全部取消勾选**:最后一个 toggle 锁住,提示「至少保留一个,想完全停用请用暂停」
- **无「分类」概念**。主题色与动画直接挂在条目上
- 副文案允许为空

### 5.3 文案规范

| 规则 | ✅ | ❌ |
|---|---|---|
| 行动指令,非信息 | 「看向窗外最远的东西」 | 「你知道吗?人每分钟眨眼 15-20 次…」 |
| 不含具体时长 | 「站起来,走两步」 | 「起身走动 3 分钟」 |
| ≤ 12 字,2 秒读完 | 「去接杯水」 | 「请远眺 6 米外物体以缓解睫状肌痉挛」 |
| 朋友腔 | 「抬头看看窗外吧」 | 「为了你的健康,你应该…」 |

**绝对不放**:冷知识、名言、励志语录、新闻、任何需要读超过 3 秒的内容。
读完之后屏幕上应该没什么可看的 —— 这是刻意的「无聊设计」,它在把用户往屏幕外推。

### 5.4 预告条

| 项 | 规格 |
|---|---|
| 时长 | 8 秒(可配 0/5/8/12/15;设 0 需提示「将无法延迟」) |
| **位置** | **通栏,紧贴浏览器地址栏下沿,压在网页最上方** |
| 尺寸 | 通栏 × 高 44-52px |
| 入场 | 从上方滑下 200ms(不用淡入 —— 滑动才能引起余光注意) |
| 倒计时 | **底边一条细进度线**整条收缩,不用数字 |
| 内容 | `emoji + 本次内容剧透` + 右侧 `空格 延迟 5 分钟` + 已延迟角标 |
| 已延迟角标 | 第 2 次起显示 `×2`(`×1` 无信息量) |
| 整条可点击 | ✅ = 延迟(鼠标用户通路) |
| 悬停暂停倒计时 | ❌ 不做(鼠标恰好停在那里会无限暂停) |
| 预告期立即开始休息 | ❌ 不做(与「点击=延迟」冲突) |

**位置选型理由:** 右下角是客服气泡/Cookie 同意/营销弹窗的地盘,用户已训练出条件反射式无视。
贴地址栏下沿是下载提示、翻译条、扩展提示的位置 —— 用户会把它读成**浏览器的提示**而非**网站的弹窗**。
一天 24 次的提醒,**被无视是最大的失败模式**。

**已知副作用(接受):** 遮挡网页顶部约 50px × 8 秒 ≈ 每天 3 分钟。

### 5.5 延迟

| 项 | 规格 |
|---|---|
| 触发 | 预告期间按空格 / 点击预告条 |
| 时长 | 5 分钟(可配) |
| **次数上限** | **无上限** |
| 延迟时长递减 | ❌ **不做**。递减有「被催促」的负面体感,可能适得其反 |
| 可见性 | ✅ 预告条显示「已延迟 ×N」—— 纯信息,零强制。自我觉察往往比外部约束有效 |
| 延迟后仍有预告 | ✅(否则到期直接黑屏更突兀) |

**自动延迟(无需按键):**
`document.activeElement` 是 `input` / `textarea` / `contenteditable`,且预告期内有 keydown
→ 自动延迟,并将预告条文案替换为 `⌨️ 正在输入,已自动延后`,2 秒后滑走。

> P4:静默的智能行为会摧毁信任。用户必须看到「它懂我」,而不是「它坏了」。

### 5.6 跳过

**方案:长按 1 秒**(已对比「延迟出现」后选定)

| 对比维度 | 延迟 1.5 秒出现 | **长按 1 秒** |
|---|---|---|
| 摩擦衰减 | ❌ 三天后练成「等 1.5 秒再点」的新反射,摩擦失效 | ✅ 永远要求一个持续 1 秒的刻意动作,不衰减 |
| 防误触 | ❌ 1.5 秒后鼠标还在那,照样误触 | ✅ 误点完全无事发生 |
| 心理 | ❌ 盯着不存在的按钮干等,纯死时间,焦虑 | ✅ 按钮一直在,「随时能走」反而更愿意留下 |
| 自我觉察 | ❌ 无 | ✅ 进度环填充 = 「我正在主动放弃休息」的可视化瞬间 |

实现细节:

- 时长 **1000ms**(800ms 易被误判为误触,1500ms 开始烦人)
- **必须有视觉进度反馈**(环形填充),否则用户以为按钮坏了
- 松手即取消,不累积
- **必须拦截 Esc**(`dialog` 的 `cancel` 事件 `preventDefault`),否则长按设计被 Esc 绕过
- 键盘通路:按住 Esc 1 秒(与鼠标行为一致)
- **跳过后:正常间隔重新计时**(不减半)
- 不做「两者都要」—— 延迟出现 + 长按 = 过度惩罚

### 5.7 休息遮罩视觉

```
                    🧍

            站起来,走两步
              让腰背松一松

                 0 : 17

            [  按住跳过  ]
```

| 项 | 规格 |
|---|---|
| 层级 | emoji → 行动指令 → 副文案(淡色)→ 大倒计时 → 跳过按钮 |
| 倒计时 | **占屏幕约 1/4 的大数字**。替代被砍掉的「结束声音信号」—— 余光可感知,无需聚焦 |
| 背景 | **深色 / 低饱和暗色**,绝不用纯白或高亮色 |
| 入场 | 渐暗过渡 300ms,模拟「屏幕关掉」,不要「啪」一下换一块亮板 |
| 出场 | 淡出 200ms |
| 亮度 | v0.2 提供滑块 |

> ⚠️ 用户刚从亮屏幕转开。全屏纯白比原网页还刺眼 —— 护眼扩展反而伤眼。

### 5.8 动画(v0.2)

**按休息方式分级:**

| 方式 | 动画 | 理由 |
|---|---|---|
| 🧍 站立 | ✅ 小人起身 | 演示动作,看一眼就会做,跨语言 |
| 💧 喝水 | 🟡 杯子微动 | 点到为止 |
| 👁 护眼 | ❌ **绝对不做** | 动画的作用是把视线粘在屏幕上,与护眼目的直接矛盾 |

**护眼反过来用「动画」把视线推走:**
1. 一个光点从屏幕中心缓慢飘向边缘后淡出 —— 眼睛本能跟随,跟到边缘就自然离开屏幕
2. 3 秒后屏幕渐暗到接近全黑,只留很暗的倒计时 —— **「没什么可看的」本身就是功能**

**纪律:**
- **播一次就停,不要循环**。循环动画在 24 次/天的频率下变成视觉噪音,且持续抓眼
- 尊重 `prefers-reduced-motion` → 直接显示静态终态
- 格式用 **SVG + CSS**(几 KB,可跟主题色变)。不用 Lottie(要 AE 源)、不用 GIF(体积+画质差)
- 若池子扩大:**按类别做 5-8 个共享动画复用**,而非一条一个(那是美术工作量,不是代码工作量)

### 5.9 抑制条件

命中任一条则**不提醒并重置周期**:

| 条件 | 检测 | 说明 |
|---|---|---|
| 用户离开 | `chrome.idle` 状态 `idle` 超过 `max(时长, 60s)` | 已经自然休息过了 |
| 系统锁屏 | `chrome.idle` 状态 `locked` | 暂停计时,解锁后从头开始 |
| **idle 期间到点** | — | **静默跳过,绝不排队等用户回来** |
| 全屏视频 | `document.fullscreenElement !== null` | **默认不打断**,设置里可开 |
| 会议站点 | 域名黑名单 | `meet.google.com` / `zoom.us` / `teams.microsoft.com` 等 |
| 手动暂停 | `pausedUntil` 时间戳 | 见 §5.10 |

> ⚠️ 最经典的差评场景:**开完 1 小时会坐下,还没碰键盘,屏幕「啪」一下黑了。** 必须避免。
> `chrome.idle` 检测间隔最小 15 秒,对 20 分钟周期完全无所谓。

### 5.10 暂停

popup 一键:**30 分钟 / 1 小时 / 今天不再提醒 / 直到手动恢复**。

实现:一个 `pausedUntil` 时间戳。

> 「今天不再提醒」一个按钮覆盖了「工作时间段」90% 的场景,且不需要用户提前配置任何东西。
> **工作时间段 / 周末自动关闭留到二期**,等真的觉得每天手动点一次烦了再说。

### 5.11 popup

```
┌────────────────────────────┐
│   下次休息  14:32           │
│                            │
│   🧍 站起来,走两步    ◉    │
│   👁 看看窗外最远的地方  ○   │
│   💧 去接杯水          ○    │
│                            │
│   间隔 [20] 分  时长 [20] 秒 │
│                            │
│  [ 立即休息 ]   [ 暂停 ▾ ]  │
└────────────────────────────┘
```

**v0.1 不做 options 页** —— 3 个开关塞得进 popup,少一个 entry point、少一套路由、少一半 UI 工作量。

### 5.12 Badge

扩展图标显示距下次休息的分钟数(`18` / `7` / `2`)。

成本极低(`chrome.action.setBadgeText`),价值:
- **预期管理** —— 知道还有 3 分钟,会自然把手头的事收个尾,大幅降低被打断的痛感
- 「这扩展还活着」的唯一可见信号

### 5.13 浏览器外提醒

浏览器不在前台(`chrome.windows.getLastFocused().focused === false`)或页面无法注入
→ `chrome.notifications` 系统通知(可穿透到桌面)。

优先级低(用户明确表示「浏览器外提醒就够了」),**排在 v0.2**。

> **必须诚实承认的硬边界:** 全屏遮罩只能盖住浏览器标签页。用户在 VSCode / Figma / PS 里时,
> `chrome.idle` 仍正确判定为 active,但遮罩弹不出来。
> 本扩展对「浏览器占工作时间 70%+」的人是完整产品,对重度 IDE 用户只是半个。

### 5.14 统计(v0.1 埋点 / v0.2 展示)

**定位:调参助手,不是成绩单。**

| ❌ 不做 | 理由 |
|---|---|
| **streak(连续天数)** | 制造「不能断」的焦虑,与「让你放松」自相矛盾。且断了之后用户往往直接放弃整个工具 |
| 突出展示跳过率等负向指标 | 产生内疚,而内疚不会让人更愿意休息,只会让人不想打开 popup |

**做的形态(按条目统计):**

```
  本周
  🧍 站起来,走两步   完成 42 · 跳过 6
  💧 去接杯水        完成 3  · 跳过 19

  💡 你几乎总是跳过「去接杯水」,要不要取消勾选它?
                              [ 取消勾选 ]  [ 不用 ]
```

跳过率从「你的失败」变成「设置的信号」,内疚消失,且给出**一键可执行的具体动作**。

> **v0.1 就要埋点,即使不展示。** v0.1 的目的是自用两周验证设计;
> 若不记录,两周后只有模糊的主观印象,没有任何事实。
> 「我两周跳过了 40%」这个数字会直接告诉你间隔该不该调、长按一秒是不是太容易跳。

### 5.15 首次使用

> 竞品真实差评:*「装了之后点图标什么都没有…用户会以为这是个假的没用的扩展 —— **他们不会等 20 分钟**。」*

- 安装后立刻打开 onboarding 页(**直接复用 `break.html`**),3 秒内让用户看到遮罩长什么样
- popup 里放「预览」按钮,随时能看
- onboarding 顺便教「按住跳过」和「预告期按空格延迟」

## 6. 自定义边界

| 层级 | 能力 | 结论 |
|---|---|---|
| 1 | 间隔 / 时长 | ✅ v0.1,**后果预览**代替硬限制 |
| 2 | 勾选参与随机的条目 | ✅ v0.1(**勾选本身即是自定义**) |
| 3 | **编辑这 3 条的文案** | ✅ v0.2 —— 3 条时「改文案」≈「加条目」,但只需三个输入框而非一套 CRUD |
| 4 | 添加新条目 | ⏸ 等池子涨到 10 条以上再说 |
| 5 | 主题 / 亮度 | ✅ v0.2 |
| 6 | 背景图 | 🟡 **内置 3-5 张远景照片供选,不做上传**(80% 价值,5% 成本) |

**明确不做:**

| ❌ | 理由 |
|---|---|
| 自定义 HTML / CSS / JS | Web Store 远程代码政策是硬线;自定义 CSS 会搞坏 iframe 布局,支持成本无限 |
| **绝对时间点提醒** | 会把产品拉回通用 reminder,破坏单一用途,数据模型复杂度暴涨 |
| 自定义提醒音 | 声音整条已砍(见 §9) |
| 多套情景配置(工作/周末模式) | 「暂停 / 今天不再提醒」已覆盖 90% 场景 |
| 自定义字体 | 没人需要(但默认字号要够大) |

**可选小花样:间隔随机抖动 ±3 分钟** —— 打破「快到点了」的提前焦虑。
纯口味问题,做成设置项**默认关**,成本一行 `Math.random()`。

## 8. 上架考量

| 项 | 结论 |
|---|---|
| 单一用途 | 「定时休息提醒」—— 干净。**守住:只支持间隔循环,不支持绝对时间点** |
| 权限 | `alarms` `storage` `idle` `notifications` + `host_permissions: <all_urls>` |
| `<all_urls>` 理由 | 「注入休息覆盖层,**不读取任何页面内容**」—— 对护眼扩展站得住 |
| 隐私 | 零数据收集,可直接勾 "does not collect user data"。这是卖点 |
| 权限策略 | **初版就按上架标准做 host permission**,别先 optional 再改(改权限模型要重新过审) |
| 市场预期 | 同类扩展用户数多在 42 / 319 / 770 量级,大量 0 评分。**别指望用户量**。但做到桌面端 Stretchly 的水准(预告 + idle + 真全屏 + 自动倒计时)在这个池子里就是断层第一 |

## 9. 决策记录:被否决的方案

| 方案 | 否决理由 |
|---|---|
| **三个独立 profile(护眼/站立/喝水)各自计时** | 一天打断 30-41 次,产品会被卸载。改为单 timer + 勾选制后降至 24 次 |
| **基准周期 + 每 N 轮一次长休息** | 基于「遮罩必须包住整个活动」这一错误前提。遮罩是触发器不是容器,矛盾不存在 |
| **内容条目的 `minSeconds` 字段过滤** | 同上。改为撰稿规范「文案不含具体时长」,复杂度归零 |
| **25-40 条内容池 + 分类** | 过度设计。一天 24 次,第四天起用户不读文字 —— 遮挡是功能,文案是标签。改为 v1 发 3 条 |
| **「分类」概念** | 3 条谈不上批量操作;主题色/动画可直接挂条目上。数据模型里一并删除 |
| **结束提示音** | 用户判定冗余。**技术红利:整个 `chrome.offscreen` 可以不做**(content script 里 `audio.play()` 受页面 autoplay policy 限制) |
| **strict mode(不可跳过)** | 有强行关闭按钮即可,默认开会吓跑所有人 |
| **延迟次数硬上限 / 延迟时长递减** | 递减有「被催促」的负面体感,可能适得其反。改为仅显示「已延迟 ×N」,观察两周再说 |
| **跳过按钮延迟 1.5 秒出现** | 摩擦会被学习掉(三天后变成「等 1.5 秒再点」的新反射)。改为长按 1 秒 |
| **秒级精度 / offscreen 精确计时** | 20 分钟周期下 ±30 秒无感 |
| **绝对时间点提醒 / RRULE** | 破坏单一用途,数据模型复杂度暴涨 |
| **预告条放右下角** | 右下角是客服气泡/营销弹窗地盘,用户已训练出条件反射式无视 |
| **streak 连续天数** | 制造焦虑,与「让你放松」自相矛盾;断了之后用户倾向放弃整个工具 |
| **自定义背景图上传** | base64 撑爆 storage 配额 + 裁剪/预览工作量。内置 3-5 张拿 80% 价值 |

## 10. 待验证的风险

| 风险 | 验证方式 |
|---|---|
| 浏览器外覆盖率不足(IDE 用户) | 自用两周,看实际漏提醒比例 |
